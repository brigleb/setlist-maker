Setlist Maker — how a set becomes a tracklist

One audio file goes in; 30-second slices are Shazam'd one at a time; the noisy matches are deduplicated and corrected into a tracklist written as .md + .json, which you can then polish in an editor and embed as podcast chapters. Amber tags mark where the open GitHub issues live.

The open issues, mapped

  • #10 tui editor · playback p previews the selected track's 30-second window; there's no seek/scrub within it. The web editor's scrubber is the workaround.
  • #24 dedup · the shared confidence bar Now that smoothing and the singleton filter both gate on --singleton-confidence, one number decides both. The 0.6 default was tuned for the filter alone and sits below what estimate_confidence() gives a clean single match (~0.667), so A·B·A smoothing rarely fires on real sets. Open question, not a regression — wants data from real runs before anyone picks a new number.
  • #44 round trip · the track line A track with a blank artist but a real title is written as 1. **** - Title (3:00), which the parser can't match — so the row is silently dropped the next time the file is read, taking its chapter with it. One move away in the browser editor: ＋ Add below, type a title, leave the artist empty.
  • #45 round trip · the track line A title carrying its own (1:23)-shaped parenthetical ends the title there and is read as the timestamp: Intro (1:23) Live at 0:00 comes back as Intro at 1:23 — wrong place in the set, wrong chapter start. (Remix)-style parentheticals are fine.
  • #16 reopen path · fixed in PR #43, pending merge A set description containing numbered, track-looking lines used to be misparsed when the .md came back in — the description was lost and a phantom track appeared, at the head of the list, out of order, taking a bogus chapter into the MP3. The description is now fenced in <!-- summary --> markers that render as nothing, and those lines are excluded from every other scan, so anything you type survives a reopen. Older, unfenced files still parse, and upgrade on their next save.
  • #7 dedup · smoothing — closed aug 2026 Smoothing used to erase a confident short track sandwiched between two longer ones (A·B·A). It's now confidence-aware: only an outlier below --singleton-confidence gets absorbed, so short cuts survive without --no-smoothing fragmenting the long tracks.
  • #13 web editor · closed aug 2026 Insert a missed track — shipped in PR #15 ("＋ Add below" with inline timestamp). Verified and closed.
  • #14 web editor · closed aug 2026 Larger, editable set description — shipped on main (88e7f38 → 3b2da85). Verified and closed.

Before you run it

time it takesAn hour-long set ≈ 120 samples ≈ 30–40 minutes at the default 15-second delay. Ctrl-C is safe; the run resumes from <name>_progress.json.
icloud filesIf the source lives in iCloud, let it finish downloading first — or expect the TruncatedAudioError guard to stop a partial decode (that's it working).
reruns are freeAn existing tracklist is reused, never re-Shazam'd, unless you pass --reidentify. Reopening the .md goes straight to an editor.
it learnsFixes accepted in either editor land in corrections.json and auto-apply to every future run. --no-learn opts out.

Common invocations

setlist-maker set.mp3              # identify → print → write set.md + set.json
setlist-maker set.mp3 -w           # …then review in the browser editor
setlist-maker set.mp3 --edit       # …then review in the terminal editor
setlist-maker set.md -w            # reopen an existing tracklist
setlist-maker set.mp3 --chapters   # full run, then embed ID3 chapters
setlist-maker chapters set.md --audio set.mp3
